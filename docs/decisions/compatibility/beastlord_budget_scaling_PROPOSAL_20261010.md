## 建议

仅调整兽主AddADCGroup=5。明确标注兽主奖励百分数的关卡，采用全局基准：

`该关兽主预算 = 四舍五入(2500 × 官方兽主奖励百分数 / 100)`

例如100%=2500、200%=5000、440%=11000。2500是本方案需要批准的数值，依据是保留第一章晦月现有5000预算。百分数来自官方SectionTable.NameMoreChina，但将其解释为加权价值预算倍率是本方案的兼容选择，并非证明官方曾这样计算。

保持另外26组的原分档预算。金币、材料等不能跟随兽主440%一起扩大。单件兽主仍使用官方星级/物品价值计算，候选掉落、星级掷骰、DroopLimit白名单和DroopLimit3星级限制保持客户端规则。

### 战令为何暂保留5000

1800个战令配置都标难度10，描述只是血月难度说明，未给兽主奖励百分数。若直接沿用上述440%曲线，1800条全部从5000升11000，候选多的关卡会明显增加装备产出，却没有逐层倍率依据。本推荐第一阶段明确保留5000，并在逐关清单列出它们。批准通用曲线不等于批准战令扩容；未来战令按层数/波次提高预算需另给曲线和实际收益样本。不得在一场战斗切波次时反复重置并获得完整额度。

## 单件价值与玩家能感受到的差异

公式保持`floor(EquibStage[quality].EquibValue × Item.ItemValue /1000) × 数量`，按组累计。以ItemValue=200兽主为例：

| 星级 | 单件消耗 |
|---|---:|
| 1★ | 160 |
| 2★ | 240 |
| 3★ | 336 |
| 4★ | 560 |
| 5★ | 720 |
| 6★ | 1000 |

第一章晦月5000和血月11000，在只产生该种6★且没有其他兽主消耗额度的情况下，价值上限分别允许5件和11件。现实中星级、物品种类混合，实际6★成本900～1200，所以只算6★约为4～5件与9～12件；这是理论额度上限，不是保底或实际平均。

预算只能减少被上限拒绝的掉落，不能增加怪物产生候选的概率，也不改变6★概率。候选总价值本来只有4000时，5000→11000仍不会多掉一件。预算放宽后“倍率对应价值上限”可以严格成立；“每场数量/平均掉落率对应倍率”必须测量，不能靠预算承诺。若预算一直不触顶，单改预算无法实现用户期待的收益差异；届时应先报告并审查下一方案，不能私自另发装备补差。

固定首通、任务、宝箱与扫荡奖励属于独立发奖路径；如其含兽主，须列入收益报表、核对来源，不给它们重复套战斗预算倍率。本轮清单审计的是客户端战斗掉落预算。保留原固定奖励与实际体力消耗；比较时同时统计每场及每30体力获得的加权价值，不能只按件数判断难度收益。

4. 对100个官方倍率关卡和110个兼容曲线关卡逐关复核；实际收益采样先覆盖第一/中间/最后章全部难度，再覆盖现世复刻、新血月、战令与未知难度代表关卡。每个代表关卡至少30次成功通关，记录掉落件数、星级、加权价值、价值利用率、每体力收益及已有固定奖励；波次较多和掉落密集地图单列。30次用于初步诊断，不作严格概率证明。
5. 若能获取候选和预算拒绝记录，比较旧/新预算对相同候选序列的接受量，识别实际触顶；仅结算总值不能证明触顶或拒绝率。若多数代表关卡明显未触顶，先解释为什么放宽无效，再提交候选概率/产量方案审查。
6. 回归正常掉落结算、装备实例属性、重试幂等、失败退出、不重复发奖以及恢复战斗；备份活跃库。按用户要求，代码实施后重启服务端，报告采用的规则版本和测试结果。
7. 回滚只撤销新预算配置，不删除已合法发放的装备；回滚时已有战斗保留进入时版本，新战斗用旧策略。
